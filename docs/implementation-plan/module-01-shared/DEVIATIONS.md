# Module 1: Deviations & Implementation Decisions

Decisions, workarounds, and changes made during implementation that differ from or extend the original spec.

---

## Docker / Database

- **PostgreSQL mapped to port 5433** (not 5432): A local PostgreSQL instance was already running on 5432. Docker container maps `5433:5432`. Default connection URL uses `127.0.0.1:5433`.
- **`127.0.0.1` instead of `localhost`**: On Windows (MINGW64), `localhost` can resolve to IPv6 `::1` which Docker doesn't bind to. All connection strings use `127.0.0.1` explicitly.
- **Redis added to docker-compose in Phase 1.3** (spec says Phase 1.4 task 1): Redis was included alongside PostgreSQL in docker-compose.yml during Phase 1.3 since the file was being created anyway.

## TypeScript / Tooling

- **Root `tsconfig.json` created**: Added a root `tsconfig.json` with project references to all packages. Required for `tsc -b` to work across the monorepo. Not in the original task list.
- **Root `type-check` script changed to `turbo type-check`**: The original `tsc --noEmit` at root doesn't work with composite project references. Changed to delegate to Turborepo which runs per-package.
- **`pnpm-workspace.yaml` uses pnpm 10.x format**: Spec mentions pnpm 9.x but 10.32.0 was already installed. Works the same.
- **Biome auto-fixes import ordering**: Biome's `organizeImports` rule reorders imports alphabetically. All source files follow this convention.
- **`esbuild` peer dependency warning**: vitest/vite 8 wants `esbuild@^0.27.0` but drizzle-kit brings `0.25.12`. No functional impact — just a warning.

## Contracts Package

- **Union types instead of enums**: `MemberTier`, `OrderStatus`, etc. are TypeScript union types (`"free" | "verified" | "pro"`) not `enum`. Union types are more idiomatic, tree-shake better, and have zero runtime cost — matching the "zero runtime deps" constraint.
- **`EventMap` type added**: Not in spec — added a `EventMap` type mapping event type strings to their payload types. Enables typed queue factory and event bus.
- **Input types added**: `RegisterInput`, `LoginInput`, `ListingCreateInput`, etc. were added alongside the domain types since interfaces reference them. Spec only lists the output types.

## Shared Package

- **`@vvs/shared` has sub-path export `./config/env`**: Added so `apps/api` can import `loadEnv` without pulling in all of shared's heavy dependencies (bullmq, drizzle, etc.) at the top level.
- **`ConflictError` has no explicit constructor**: Biome flagged it as `noUselessConstructor` since it just calls `super(message)`. Removed — the base `AppError` constructor handles it.
- **`postgres@3.4.8` used (not `pg`)**: Spec doesn't specify driver. `postgres` (postgres.js) was chosen for its ESM-native design and compatibility with Drizzle's postgres-js adapter.

## Fastify API

- **`FastifyRequest` augmented via `declare module`**: Fastify's `decorateRequest` pattern requires TypeScript module augmentation for type safety. Added `correlationId` to the request interface.
- **Rate limiting uses in-memory store (not Redis) initially**: `@fastify/rate-limit` is configured but without a Redis store yet. Will switch to Redis backend when auth middleware is added.
- **Per-user and per-route rate limits deferred**: Tasks 15-17 (authenticated rate limits, sensitive endpoint limits) deferred to Module 2 (Auth) since they depend on auth middleware existing.

## Files Not in Spec

- `migrations/0000_dusty_invisible_woman.sql` — auto-generated by drizzle-kit, name is random
- `migrations/meta/` — drizzle-kit migration metadata (journal + snapshots)
- `apps/api/src/schemas/common.ts` — shared JSON schema fragments for Fastify routes
- `packages/shared/src/events/in-memory-bus.ts` — test-only event bus (no Redis needed)
- `packages/shared/src/config/env.ts` — Zod env validation (sub-path exported)
